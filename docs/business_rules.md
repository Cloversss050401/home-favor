# 家庭 AI 食谱推荐系统 · 业务规则

本文档汇总系统硬性业务规则及实现位置，作为开发与验收对照。

## 1. 成员档案规则

- 单家庭最多 **8 位成员**（`FamilyService.create_member` 校验 `MEMBER_FAMILY_LIMIT`）。
- 年龄范围 **0-120 岁**，允许婴幼儿小数年龄（如 0.67 ≈ 8 月龄），校验在 DTO 层。
- 女性/男性饮食目标映射 DRIs 人群：`baby_6_12m`（婴幼儿辅食）/ `pregnant`（孕妈）/ `elderly`（老年）/ `adult_male` / `adult_female`（减脂增肌等按性别）。
- 过敏原与忌口必须参与食谱生成提示词，避免过敏食材入菜。
- 成员删除一律**逻辑删除**（is_deleted=1），禁止物理删除。

## 2. 营养计算规则（核心）

- 核心营养素 **6 项**：蛋白质、钙、铁、锌、维生素A、维生素C（`constants.CORE_NUTRIENTS`）。
- 营养数据唯一权威源：**MySQL `food_nutrition`（中国食物成分表）+ `dris_standard`（DRIs）**，不信任模型返回数值。
- 缺口占比公式：`(RNI − 实际摄入) / RNI × 100%`；**仅当实际摄入 < 推荐值才计缺口**，达标/超量为 0。
- 缺口状态分级：`ok`（无缺口）/ `gap`（缺口 ≤30%）/ `big_gap`（缺口 >30%）。

## 3. 智能采购触发规则

- 触发条件（任一）：① 任意成员核心营养素缺口 **>30%**；② 共享主菜数 **<2**。
- 采购量满足**全家 3 天需求**：`∑(成员 RNI − 现有摄入) × 3`（按缺口大小补充对应食材）。
- 已录重量的食材按现有存量**扣减**，扣减后 ≤0 的从采购清单移除；未录重量的仅标记不扣减。
- 采购项优先级：P0（缺口>50%）/ P1（缺口 30-50%）/ P2（缺口 ≤30% 补充）。

## 4. 食材录入规则

- 三种入口（文字/拍照/语音）统一：`解析名称+重量` → `同义词归并到规范名` → `确认入库`。
- 语音/文字支持一次录入多种食材，按顿号、逗号、分号、竖线、换行等分隔符切分。
- 食材无重量时 `available_weight` 允许为空（仅记录存在），不参与扣减。
- 食材失效采用 `is_valid=0` 逻辑删除。

## 5. AI 食谱生成规则

- 输入：全部成员档案（年龄/性别/目标/体质/健康/过敏/忌口）+ 家中现有食材 + 期望菜品数。
- 输出三层结果：① 全家共享菜品；② 每位成员分餐方案 + 双维度营养评估（摄入优点/营养缺口）；③ 智能采购清单。
- 生成后必须经 `NutritionService.local_verify_allocation` 用本地食物成分表**二次校验**：仅有本地识别到数据的项才覆写模型数值，防止模型幻觉。
- 完整三层结果 + 输入快照整体落库（`recipe_generation_record`），支撑反馈折算与周报。

## 6. 反馈与周报规则

- 反馈记录：成员 + 实际制作菜品 + 食用分量 + 食用日期；支持「一键全选复用 AI 分量」（use_ai_amount=true 时按 AI 方案分量直接入库）。
- 周报折算链路：`user_feedback → 菜品食材配比分解（优先取生成记录 main_ingredients 等比例缩放）→ 查食物成分表 → 单餐营养素 → 按天/按周聚合`。
- 菜品名无配比信息时降级：直接以菜品名作为单一食材查询成分表。
- 周报产出：达标率（每营养素满足天数/有效天数）、累计缺口、超标项、下周建议；支持手动生成，预留每周日自动生成（generate_type=1）。

## 7. 数据同步与删除

- 删除一律逻辑删除（is_deleted / is_valid），对外查询全部过滤已删数据。
- 外键关系：反馈 → 生成记录 SET NULL（记录删除不丢反馈）；反馈/食材/周报 → 家庭/成员 CASCADE。

## 一、整体架构总览

采用 **前后端分离 B/S 网页应用**

```
前端网页(浏览器) ↔ 后端服务 ↔ 外部能力API(大模型/OCR/语音) ↔ 本地业务数据库
```

- 前端：负责页面交互、档案录入、食材录入、结果渲染、导出下载
- 后端：业务逻辑、数据持久化、参数组装、调用外部 AI 能力、营养计算、周报统计
- 外部 API：大模型、OCR、语音识别
- 数据库：存储家庭档案、食材、菜谱、用户反馈、周报数据

## 三、AI 食谱引擎实现方案（核心模块）

> 问题点：调用哪家模型；档案 + 食材如何构造 Prompt 输入；营养计算；菜品来源（自建库 or 模型生成）

### 3.1 大模型选型

**主选：通义千问 / 豆包大模型 API（字节）**备选：GPT‑4o、文心一言

> 理由：支持结构化 JSON 输出，方便解析食谱、分餐、营养评估；中文菜谱知识充足。不使用本地开源大模型（硬件成本高，效果不稳定，网页项目不适合）。

### 3.2 输入构造：档案 + 食材组装 Prompt

后端负责把数据库取出的数据组装大模型 Prompt，不要前端直接传给大模型。传给大模型上下文包含：

1. 家庭全部成员档案：每个人年龄、性别、饮食目标（减脂 / 增肌 / 孕妈 / 8 月龄宝宝等）、体质、慢病、过敏原、忌口清单
2. 当前家中可用食材列表
3. 约束规则：
   - 优先使用现有食材生成全家共享菜品
   - 输出必须包含：共享菜品清单、每个人分餐分配、【摄入优点】【营养缺口】
   - 营养素计算必须参考《中国居民膳食营养素参考摄入量 DRIs》
   - 若营养素缺口 > 30% 输出采购清单，标注优先级、缺失营养素、建议采购量
4. 强制要求大模型返回**标准 JSON 格式**，后端直接解析 JSON，不解析自由文本，避免乱输出。

### 3.3 菜品数据来源策略（混合模式）

1. **自建基础菜谱库（MySQL 存储）**：存入家常菜基础信息：菜名、主要食材、烹饪方式、基础营养参考值；优先从自建库挑选菜品。
2. 当自建库匹配不到合适组合，交给大模型做合理生成。

> 不全部依赖模型自由生成，避免出现不合理菜谱。

### 3.4 营养缺口计算逻辑（两层校验）

1. **第一层：大模型给出粗评估**（在 JSON 输出返回各成员营养素占比、缺口）
2. **第二层：后端本地二次校验**：后端读取【中国食物成分表】，结合分餐分量，计算实际摄入，对比 DRIs 标准，修正大模型输出，输出最终缺口。

> ⚠️不能完全信任大模型算营养，后端必须做本地校验，防止幻觉。

### 3.5 超时控制

调用大模型接口设置超时 30 秒，匹配产品文档描述 10‑30s 生成；超时返回提示 “生成食谱超时，请减少食材或稍后重试”。

## 四、食材拍照识别 OCR / 多模态方案

> 需求：拍照识别食材；识别错误需要纠偏兜底

1. **选型：大模型多模态能力（豆包多模态 / 通义千问多模态 API）**

- 上传食材照片，API 返回识别到的食材列表 JSON。

1. 纠偏兜底逻辑（非常重要）
   1. API 识别返回后展示识别结果列表给用户；
   2. 用户可以手动删除错误识别食材、新增遗漏食材；
   3. 用户必须点击【确认食材】按钮，确认后的列表才进入业务流程；

> 不把识别结果直接当做最终输入，**必须经过人工确认，解决识别错误问题**。

1. 备选方案：通用 OCR（如 PaddleOCR），适合包装文字拍照，生鲜食材识别弱，仅做降级备用。

## 五、武汉方言语音录入 ASR 引擎

> 需求：支持武汉方言语音录入食材

1. 选型：火山语音 ASR / 阿里云语音识别
   - 开启方言模式：选择「武汉话 / 湖北方言」识别场景；
2. 流程：前端录音，把音频流传给后端，后端调用 ASR 接口转文字；返回文字展示到页面，**仍然需要用户确认、手动修改纠错**，确认后作为食材输入。

> 风险点：方言识别不能做到 100% 准确，必须有人工确认兜底，不能直接作为最终食材。

1. 备选：如果预算有限，关闭方言，先做普通话，后期再打开武汉方言能力。

> 一期三大录入方式：拍照识别、文字输入、方言语音录入全部支持，都带人工确认兜底。

## 六、营养数据源确定（营养缺口计算依据）

> 没有这个数据源，营养缺口完全没有依据。

1. 两份核心数据源，存入 MySQL 数据库
   1. 《中国食物成分表》标准版：每一种食物编码、名称、每 100g 的蛋白质、碳水、脂肪、各类维生素矿物质含量。
   2. 《中国居民膳食营养素参考摄入量 DRIs》：不同年龄、性别、生理阶段（孕妇、乳母、婴幼儿、老年人）每日推荐摄入营养素参考值。
2. 使用方式：后端本地查表计算。当得到某成员吃 XX 克豆腐、XX 克鸡胸肉，后端循环查表累加总摄入；对比 DRIs 标准，计算缺口百分比、缺口绝对值。

> 重要：**营养计算主体在后端本地，不是完全交给大模型，大模型只做辅助。**

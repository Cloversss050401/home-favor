# 家庭 AI 食谱推荐系统‑业务规则补全方案.md

> 
> 补全项目缺失业务定义：食材录入粒度、营养缺口口径、反馈转周报折算逻辑、家庭档案交互规则、采购清单粒度与合并规则。
> 前面技术方案的配套业务规则，没有这些定义，开发出来逻辑会模糊、结果不一致。

## 一、食材录入粒度：录入「番茄」还是「番茄 500g」

### 问题

原始文档没有定义，直接影响菜谱匹配、剩余食材消耗、采购量计算。

### 最终业务定义

> 
> 家庭现有食材分为两个字段：**食材名称（必填） + 当前可用重量（选填）**

1. 用户录入时：
   - 最小识别粒度：食材名称，例如：`番茄`、`鸡胸肉`。
   - **重量为可选填写项，不强求用户必须输入**。
   - 三种录入方式（拍照 / 文字 / 武汉方言语音）：
     - 拍照、方言语音优先识别食材名；能识别到重量就回填重量，识别不到重量则重量字段留空。
     - 文字输入支持两种写法：`番茄` 或者 `番茄 500g`，后端自动拆分名称与重量。
2. 菜谱匹配逻辑
   - 匹配优先看**食材名称**，不依赖重量；只要家里存在该食材名称，就允许生成菜谱使用。
3. 重量存在 / 缺失两套分支逻辑

表格

| 场景 | 处理逻辑 |
| --- | --- |
| ✅ 用户填写重量（番茄 500g） | AI 生成食谱时尽量在该重量范围内设计菜品；计算采购时对比现有重量，算出还缺多少克。 |
| ❌ 用户未填写重量，仅录入名称「番茄」 | 系统只知道家里 “有这个食材，但不知道多少”；菜谱正常生成；**不做剩余重量扣减；采购清单不会因为已有该食材就扣减重量，仅做 “该食材家中已有，优先消耗，尽量不再重复采购” 标记**。 |
4. 数据库表 `household_ingredient` 修改
增加字段：`available_weight decimal(10,2)` 可用重量；`weight_unit varchar(10)` 单位，默认`g`；可为 NULL。

> 
> 用户界面交互：识别出来的食材列表，每一行后面可以手动修改重量，不填也可以确认提交。

> 
> 重要：一期**不做食材消耗扣减**。
> 即做完菜之后不会自动减去 500g‑200g=300g；家庭食材列表由用户自己维护，手动删除 / 修改。
> 自动扣减食材消耗复杂度很高，放到二期迭代。

## 二、营养缺口口径：核心营养素缺口＞30%，哪些营养素、按什么基准计算

原始文档：“核心营养素缺口超 30% 触发采购清单”，没有明确定义。

### 1. 定义「核心营养素集合」

> 
> 触发采购判断使用的核心营养素：
> `蛋白质、钙、铁、锌、维生素A、维生素C`
> 其余营养素（B 族、钾镁等）只做展示，**不参与采购清单触发条件判断**。

### 2. 缺口计算公式（后端本地计算，不是模型输出）

```
个体每日推荐值RNI（取自DRIs表，按年龄/性别/生理状态）
实际摄入 = ∑(食材克数 × 每100g营养素含量 /100 )

缺口绝对值 = RNI − 实际摄入
缺口占比 = 缺口绝对值 / RNI × 100%
```

> 
> 只统计：缺口占比＞0 才叫缺口；如果实际摄入大于 RNI，缺口为 0，不计入。

### 3. 触发采购清单完整规则

> 
> 原始条件：核心营养素缺口＞30%，或主菜不足 2 道触发采购清单。
> 补全完整逻辑：

1. 单个人，**任意一项核心营养素缺口占比＞30%**
OR
2. 本次生成方案主菜数量＜2 道
👉 触发智能采购清单。

> 
> 注意：只要家庭里**任意一个家庭成员命中条件，就触发采购清单**；采购清单优先针对缺口最大成员进行食材推荐。
> 页面展示：每个成员营养缺口所有营养素都展示（含非核心），但只拿上面 6 种做触发判断。

## 三、反馈→周报的折算逻辑：用户勾选菜品 + 填写食用分量如何换算周报营养数据

### 问题

用户勾选做了哪些菜，输入食用分量，如何折算成每个人的营养素摄入，汇总周报告。

### 数据流链路

> 
> 用户反馈表 (user_feedback) → 单餐每个人营养素汇总 → 按天聚合 → 按周聚合 → weekly_nut_report 周报

### 换算步骤

1. 基础数据来源：
   - 本次食谱生成记录 `recipe_generation_record` 里面共享菜品；
   - 用户反馈：勾选实际做的菜，为每一位成员填写**实际食用分量（g）**；支持一键全选（代表完全按照 AI 推荐分量食用）。
2. 单餐单成员营养素计算：
   - 根据菜品拆解食材配比（自建菜谱库中存储每道菜品各食材占比）；
   - `该成员吃这道菜的克数 × 菜品中各食材占比 → 得到该成员吃的各原始食材克数`
   - 查询`food_nutrition食物成分表`累加得到该成员本次吃饭各类营养素摄入。
3. 按天聚合：同一个家庭同一天多条反馈记录，同一个成员所有餐次营养素累加，得到**该成员当日总摄入**。
4. 按周聚合（周一～周日，和系统约定统计周）
   - 周总摄入 = 本周内每一天有效反馈记录营养素之和
   - 周参考基准：DRIs 每日推荐值 × 本周有效记录天数（只统计用户有提交反馈的天数，不补全无记录空白天）
   - 周达标率 =（实际周摄入 ÷ (RNI × 有效记录天数)） ×100%
   - 周累计缺口 = (RNI × 有效记录天数) − 实际周摄入

> 
> ⚠️重要规则：
> 
> 
> 1. 如果当天用户没有提交任何做菜反馈，**不做估算，不自动补数据，视为当天无记录**，不参与周报统计；不 AI 脑补饮食。
> 2. “一键全选” 含义：直接复用 AI 食谱推荐的每个人分配分量作为实际食用分量。
> 3. 用户可以手动修改分量，手动输入值优先级高于一键全选。

> 
> 周报输出字段：达标率、累计缺口、超标项；超标判断：实际摄入＞1.2×RNI 则标记为超标。

## 四、档案交互细节：字段校验、成员上限、删除成员历史记录处理

表：`family_member`家庭成员档案表

### 1. 字段校验规则

表格

| 字段 | 校验规则 |
| --- | --- |
| 姓名 | 非空，最长 20 字符 |
| age 年龄 | 0‑120；0 代表婴儿，允许小数，例如 8 月龄填 0.67；不允许负数 |
| gender 性别 | 枚举：男 / 女 |
| physique 体质类型 | 枚举集合：气虚质、体质偏寒、平和质、阴虚质、湿热质；允许多选 |
| health_condition 健康情况 | 枚举集合：无、高血压倾向、糖尿病倾向、孕早期、孕中期、孕晚期、哺乳期；允许多选 |
| diet_goal 饮食目标 | 枚举集合：无、减脂、健身增肌、宝宝辅食；单选 |
| allergy 过敏原 | 枚举（常用）：海鲜、鸡蛋、牛奶、花生、小麦；同时支持用户自定义输入，JSON 数组存储。生成食谱时直接过滤含过敏原食材。 |
| food_restrict 忌口 | 用户自定义文本数组，无强制枚举，自由输入。 |

### 2. 家庭成员上限

- 一个家庭`family_id`下，最多保存 **8 位家庭成员**；满足普通大家庭场景。超过提示 “最多添加 8 位家庭成员”。

### 3. 删除成员后历史记录处理（重点）

> 
> 不能物理删除数据库行，否则历史食谱记录、周报无法解析旧数据。

1. 业务采用**逻辑删除**：`is_deleted tinyint 0未删除 1已删除`，增加到此表。
2. 用户前端 “删除成员” 操作：设置 is_deleted=1，前端不再展示该成员，新生成食谱不再读取该成员。
3. **历史数据保留策略**
   - 旧的`recipe_generation_record`、`user_feedback`、`weekly_nut_report`保留原有 JSON 数据不变；历史周报依旧可以查看。
   - 已逻辑删除的成员，不再参与新的周报统计。

> 
> 禁止物理 DELETE member 行，否则历史全部乱掉。

## 五、采购清单粒度：按几人・几天计算采购量，同类食材合并、导出表格字段

### 1. 采购量计算口径

> 
> 采购清单为**1 个家庭，满足全家 3 天补充需求**（一期固定 3 天，二期可配置天数）。
> 计算基准：基于触发本次生成食谱时所有家庭成员的 DRIs 每日推荐值 ×3 天 − 当前已有食材可供给量（如果用户填写重量才扣减；没有填重量，则不扣减）。

### 2. 同类食材合并规则

1. 同大类食材合并：例如「鸡蛋、土鸡蛋」合并为 “鸡蛋”；后端建立食材同义词映射字典表。
2. 同一营养素可以由多种食材补充，清单按优先级排序：
   - P0 最高优先级：弥补缺口最大成员的核心营养素食材；
   - P1 次优先级：性价比高常见家常食材；
   - P2 低优先级：小众食材。
3. 合并规则：**同一种食材只出现一行，叠加总建议采购克数，不重复多条。**

### 3. 采购清单导出表格字段（导出 Excel）

导出 csv/xlsx，字段顺序：

表格

| 字段 | 说明 |
| --- | --- |
| 优先级 | P0/P1/P2 |
| 食材名称 | 采购食材名 |
| 需要补充营养素 | 例如：钙、维生素 A |
| 建议采购量 (g) | 建议购买克数 |
| 备注 | “家中已有该食材，建议按需少量补充” |

### 4. 页面展示规则

1. 如果家里已有该食材（录入过该食材名称，但未填重量）：清单中保留该行，备注标注【家中已有，建议评估存量后采购】，采购量不做扣减。
2. 如果家里已有并且填写可用重量，则采购量 = 3 天总需求 − 当前可用重量；计算结果≤0，则该食材从采购清单移除。
